# Neura v2.6.0-rc.1

Prepared: 2026-10-15. Integrated candidate updated: 2026-10-24
Channel: prerelease
Status: proposed candidate; publication gates remain open

This release is experimental and not production-ready.
Human Away remains preview-only and is not approved for unattended high-impact work.
No npm package is published by this release.

## Scope

This candidate collects the source changes since the historical published
`v2.5.1` release for supervised Windows use. It targets exact Pi `1.4.0` and
Node `24.15+`; Windows CI uses Node `24.16.0`. Linux CI exercises selected
portable contracts and does not establish a supported Linux installation.
Source archives do not include Node, Pi, WSL2, or a complete runtime bundle.

Included source changes:

- Work as the default supervised mode with network-disabled WSL2/bubblewrap
  execution, explicit approvals, and no host fallback.
- Learn Mode with practical lessons, diagrams, PDF/PPTX extraction, offline
  English OCR, bounded SQL exercises, citations, explicit save/resume, and
  optional machine-local Obsidian capture.
- Modular verification, health diagnostics, the command launcher, a local
  image-backed launch with logo-only fallback, and opt-in hashed guidance.
- Plan confidentiality hardening: canonical contained reads, ignored/private
  file exclusion, denial of historical Git content, and redacted final context.
- Coupled Pi `1.4.0` runtime/API/TUI pins and immutable guidance `1.0.4`.
  Real-loader/session controls cover new and restored tools across compaction,
  resume, tree navigation and reload, with restricted payload/dispatch denial.
  TUI checks cover CJK Markdown and dialog-stack focus cleanup.
  Native MCP and custom-startup/busy/abort controls remain.
- Neura launch and tool-free Headmaster select the sealed private unbundled Pi
  `dist/cli.js` and fixed external Undici `8.12.2`, with exact pins and a narrow
  literal override. Receipt and canonical identity checks reject invalid runtime
  paths with no global fallback. This does not replace Undici embedded in stock
  Pi's CLI/RPC bundle, update Node's built-in fetch, or change live/global Pi.
- Managed-file installer recovery and shared fail-closed prerequisite checks
  that reject drift and never downgrade a newer Pi.
- CodeQL `4.39.0`, setup-node `7.1.0`, and upload-artifact `7.0.2` actions,
  with complete commit pins and guarded draft-prerelease packaging.

The integrated candidate includes the changes from #101 (axe-core `4.14.0`),
#102 (TypeBox `1.3.36`), #103 (Playwright `1.64.0`), #104 (PDF.js `6.4.299`),
#106 (upload-artifact `7.0.2`), #110 (Node types `26.6.5`), #111 (canvas `1.0.11`),
and #112 (CodeQL `4.39.0`). The Pi `1.3.0` prerequisite merged through #109.
Each original branch is retained until the combined candidate passes review,
new-head CI and merge; inclusion here is not publication certification.

## Verification and publication gates

The Pi 1.4 source candidate has passed focused loader/session, skills, synthetic
installer, UI and configured typecheck checks. The resolved npm Undici controls
and both graph vulnerability audits pass. Full harness, browsers, signature
audits, independent review and new-head CI remain separate gates.
No live/global Pi update or clean-host rehearsal was performed.

Independent review found a bundled CLI fetch integrity bypass. Neura now avoids
that unchanged artifact by selecting its owned unbundled entry. Focused runtime,
launcher, installer, integration and approvals tests pass for the fixed path.
Independent review and required new-head CI must assess the remediation before
the High finding can close or integration can proceed. See
[dependency evidence](../DEPENDENCIES.md#scoped-npm-undici-security-patch).

Historical Pi 1.2 main `8e8e8d74b77a9e4ee81a3fd0d31bf99d7b999467` passed
[Neura CI run 38694416311](https://github.com/Rajveerx11/neura/actions/runs/38694416311),
including the Windows/portable repository checks, browser, dependency/signature,
secret-history, and ephemeral installer checks. This is prerequisite evidence,
not certification of the new versioned candidate. Required CI must pass on the
final integrated release commit.
The annotated-tag workflow then reruns the release gates before creating a draft
with source ZIP/tarball, SPDX snapshots for both locked graphs, and SHA-256 sums.

Publication remains blocked on the applicable [open-source checklist](../OPEN_SOURCE.md),

installation, and external-contributor repository checks. A GitHub draft does
not satisfy those checks. No current owner's live-install match, clean-host
bootstrap, WSL field rehearsal, or production-readiness result is claimed.

## Known limitations

- Unattended candidate execution remains blocked by [#24](https://github.com/Rajveerx11/neura/issues/24).
  Human Away's writable workspace and repository scripts are not approved for
  unattended high-impact work.
- Full cross-component installation is not atomic; bootstrap, artifact trust,
  interruption/recovery, and clean-host rehearsals remain [#21](https://github.com/Rajveerx11/neura/issues/21).
- Plan containment is application-level. Work confidentiality, integrations,
  memory, approvals, strict typing, and operational gates remain documented in
  [STATUS.md](../STATUS.md) and [PRODUCTION_READINESS.md](../PRODUCTION_READINESS.md).
- Full verified proof PASS remains unavailable under [#91](https://github.com/Rajveerx11/neura/issues/91).
  Quick detector PASS is not engineering completion; `/ship` does not publish.
- Learn's first workspace-store creation requires native Windows. Parser process
  bounds are not OS isolation; OCR can misread material and PPTX full layouts
  require PDF export. Optional Obsidian capture remains preview behavior.
- YOLO deliberately disables Neura's application approvals and tool blocking.
  Private credentials, sessions, approval history, and learning data remain local.

## Upgrade and evaluation

1. Use a separate checkout/profile and retain the previous known-good source
   and private configuration backup. Read [installation prerequisites](../../README.md#requirements)
   and [installer readiness](../INSTALLER_READINESS.md) before changing a live installation.
2. Check out the published candidate tag only after publication, verify its
   release checksums, and run `npm ci --ignore-scripts` plus
   `npm ci --prefix agent/neura --ignore-scripts`.
3. Run `npm run check:pi-latest`. Pi must match the reviewed exact contract;
   if upstream is newer, wait for the coordinated Neura update instead of
   downgrading Pi or bypassing the check.
4. Provision the documented Windows/WSL prerequisites, then run the documented
   repository, browser, sandbox, dependency/signature, and release checks.
5. Only with an intentional live-install decision, run `powershell -File .\install.ps1`
   followed by `powershell -File .\install.ps1 -Check`. Preserve user-owned
   settings, extensions, credentials, approvals, and learning files.

## Rollback

Stop Neura and external writers first. Restore a known-good compatible Neura
source/runtime graph, managed contracts, and checksums together in a separate
checkout, verify it, and use its installer only after an intentional rollback
decision. Do not downgrade a newer global Pi to make an old Neura tag pass;
choose a compatible reviewed Neura revision or pause use. Do not repair an
invalid approval audit tail or remove private Learn/vault data to force success.
Run the documented drift check after restoration. Preserve published tags and
record any correction in a new version. See [release rollback](../RELEASING.md#rollback).
