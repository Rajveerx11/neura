# Neura v2.6.0-rc.3

Updated: 2026-11-23
Channel: prerelease
Status: published prerelease, 2026-11-23. Source archive only

This release is experimental and not production-ready.
Human Away remains preview-only and is not approved for unattended high-impact work.
It is unavailable in the active CLI.
No npm package is published by this release.

## Release decision

The owner authorized this prerelease on 2026-11-23. It publishes current `main` as a
source archive with SBOMs, so the work since `v2.5.1` can be downloaded. It is not a
stable or production release. GitHub keeps the historical Pi-based `v2.5.1` as the
latest stable release.

Local checks on the tagged commit: `npm run verify`, `verify:release`, dependency and
registry-signature audits, and a Gitleaks scan of `main` history. These are not runtime
tests. Gates in [releasing](../RELEASING.md) remain open: runtime regression evidence
(the repository's runtime tests were removed, so `npm test` fails by design and the tag
workflow stops there), installer and clean-host acceptance, sandbox acceptance and
independent review. Use synthetic, non-sensitive data only.

## Included source

The commit tagged `v2.6.0-rc.3` on `main`.

- Neura's own agent loop (`src/runtime.ts`) on the AI SDK provider contract, with Work,
  Learn and YOLO. No Mastra or Pi packages and no implicit Pi credential/profile imports.
  The loop has not yet been exercised against a real provider account.
- Detector proof compares against the commit recorded at task start, never a moving ref.
- Saved sessions retain a bounded detector receipt. `/verify status` reloads it
  and checks candidate currency. Work/YOLO retain the original task identity and
  base across restart. Uncertain outcomes require inspection and `/reconcile`.
  No automatic replay occurs. `--no-history` sessions are not saved.
- Work reads/search, byte-bound writes/edits, bounded project instructions and
  offline WSL2/bubblewrap commands. Work builders allow 60 steps. Learn/reviewers
  keep eight. Gitfiles are refused for commands, and protected configuration
  paths remain read-only in command execution.
- Default Work review with read-only tools and candidate-bound receipts.
  Repair is bounded, and same-family review is labelled. No commits, pushes or merges.
- Learn active pedagogy, curriculum DAG engine, PDF/PPTX/OCR, cited HTML boards,
  proposition graph vault with typed wikilinks, exercises, explicit save/resume
  and optional minimized Obsidian capture. Hardened topic bounds and evidence
  isolation prevent cyclic or unbounded traversals.
- Approved prompt-to-result logo, startup status, answer-only chat, explicit
  approvals and plain/ASCII/narrow-terminal fallbacks.
- Interactive answers render Markdown (lists, tables, code blocks), an erasable
  activity row shows elapsed time, and typing `/` opens a live slash-command menu
  with argument completion. Piped and ACP output stay unrendered.
- Agent Skills (`$`), Work scheduling, OpenRouter and AIRouter.in gateways, and
  named tool progress (#176, #177).
- A status bar under the prompt. `!COMMAND` runs the user's own shell command as the
  user, outside the sandbox; the prompt box turns pink while the line is a command.
- Native Work subagents (#178).
- Submitting a pasted draft that wraps no longer leaves the prompt box's top border
  on screen, and interactive answers start after a blank row.
- Exact package-closure/license gates, frozen parity inventory and required
  Windows/portable CI contracts. These are not full legacy parity or release clearance.

## Limits and remaining gates

Work requires a configured Windows/WSL2/bubblewrap host for actual commands.
Dependency installation is manual. Learn-store creation requires native Windows. Browser progress returns through copied commands, and restored sources need reimport.
Subscription login/refresh/restart and entitlement coverage remain incomplete
despite recorded owner-reported working responses and live Work runs.

Plan, Human Away, MCP/LSP, delegation, context compaction and full trusted proof
are unavailable. Durable restart metadata does not provide checkpoints, undo,
crash-lock recovery, budget continuity or external-effect reconciliation. Quick
detector receipts retain `verified:false` and `testsRun:false`. Git-ignored files
without secret names can remain readable to commands. Same-user application-path
and plaintext-vault limits remain.

Release additionally needs reviewed Pi-free packaging, rights/notices,
clean-profile install/recovery evidence, independent review and required new-head
CI. See [releasing](../RELEASING.md) and [status](../STATUS.md).
[Parity](../PARITY_MATRIX.md) and [installer readiness](../INSTALLER_READINESS.md)
track unfinished implementation and setup.

## Evaluate and roll back

Follow the [current source quick start](../../README.md#quick-start-from-source)
and [development guide](../DEVELOPMENT.md). Install both locked graphs with
scripts disabled. Use disposable external projects and an optional explicitly
selected development launcher. Do not follow old Pi upgrade commands on current main.

Exit Neura before source/launcher changes. Select a known-good checkout or restore
only a verified installer-owned launcher backup. Preserve credentials, sessions,
approvals, memory, vaults, dirty worktrees and recovery backups. No automatic
rollback or live installation is performed by editing these notes.
