# Make Neura finish real tasks, then make the workflow the default

**Next feature: Real-Project Work.** Today a Work turn stops after 8 model steps without saying so, then prints raw tool output as its answer. A real coding task needs far more than 8 steps. The screenshot workflow runs on top of Work, so it comes second. If it went first, it would review half-finished code.

**The screenshot** is a three-stage loop: build with evidence, get an independent review, then ship and watch what landed. Neura already has the fresh read-only reviewer, the bounded fix loop and the rule that a review only counts for the exact code it saw. Everything else in the diagram is prompt-only or missing.

One security problem comes first. A sandboxed `npm test` can write a Git hook into the real repository, and that hook runs on Windows at your next commit. I reproduced this.

<Callout id="hook-risk" tone="risk">

**Confirmed: the sandbox can reach the host through `.git`.** `bubblewrapArguments` binds the whole workspace writable, including `.git`. A `package.json` test script wrote `.git/hooks/pre-commit`, and the file appeared in the host repository. Git would run it on Windows outside the sandbox at the next `git commit`. The approval prompt only shows `npm test`, and the review fingerprint does not cover `.git`. Treat this as a security bug. Fix it before any command runs without a prompt. Report it through the private route in `SECURITY.md`, because the repository is public.

</Callout>

## Milestone 1: Real-Project Work

**Done means:** Neura completes a task of 20 or more tool steps in a separate repository, with a real provider and a real review, and every stop is reported honestly.

### 1. Close the `.git` hole

Add `--ro-bind` for `.git` after the workspace bind in `bubblewrapArguments` (`agent/neura/human-away-sandbox.ts`), when `.git` exists. `git status` must still work inside the sandbox. This is a security-boundary change, so it needs one positive test and one negative test: the hook write fails, and `git status` passes.

### 2. Honest turn budget

Replace the single `MAX_TURN_STEPS` with a `maxSteps` option on `runTurn`. Work builder turns get 60. Learn and reviewer turns keep 8. `runTurn` returns a `stopReason`, and a turn that hits the limit no longer falls back to dumping tool output.

60 is chosen from `MAX_SESSION_MESSAGES = 200`: a step adds at least two messages, so one 60-step turn fits in history. Tune it after real use.

- **`grep` and `find` tools.** Wrap the existing `inspectPlanFiles` in `createWorkspaceTools` and add both names to `READ_ONLY_TOOLS`, so the reviewer gets them too. Learn keeps its current tool list.
- **New folders.** `write` creates missing parents. Every path part is still checked first, and the linked-parent check runs on each folder it creates.
- **Dotfiles.** Replace the blanket `part.startsWith('.')` denial with a small allowlist: `.gitignore`, `.gitattributes`, `.editorconfig`, `.nvmrc`, `.prettierrc*`, `.eslintrc*`, `.dockerignore`, `.env.example` and `.github/**`. `.github/workflows/*` needs typed approval for each write, because those files run remotely. `.env`, `.npmrc`, `.git` and every other `SECRET_PATH` match stay denied. `.env.example` gets an explicit exception in `SECRET_PATH`.
- **Project instructions.** Read root `AGENTS.md`, then `CLAUDE.md`, through `readPlanFileSnapshot`, capped at 32 KiB and redacted, and append them to the Work instructions as project guidance. They cannot widen policy.

### 4. Fewer prompts, with the fix in place

After step 1, skip the typed `yes` when `inspectAction` returns `route: 'allow'` for `work_exec`. `npm test`, `tsc`, `pytest` and `mkdir` then run on their own, still offline in the sandbox, and each prints one line. Unclassified commands still ask.

### 5. Fail fast on installs

Recognise package-manager installs in `work_exec` and return at once: `No network in the sandbox. Run this yourself in WSL, then say continue: npm install left-pad`. Install from WSL at the `/mnt/c/...` path, because Windows-built native modules are unlikely to load in the Linux sandbox.

<Callout id="m1-risks" tone="warning">

**Known limits after Milestone 1.** There is no context compaction, so very long sessions can hit provider limits. A single turn over 200 messages or 1 MiB fails its history save with a warning, while the turn itself completes. Add compaction when real use shows this happening. Neura still cannot run commands on its own checkout, by design, so use it on other repositories.

</Callout>

- **`declare_task` tool.** Input: `kind`, `summary`, optional `reproCommand`, optional `noReproReason`. `write` and `edit` are refused until it is called, so plain chat costs nothing extra. Opaque shell edits can bypass this refusal, so it is a workflow gate and the final line reports `task not declared` when that happens.
- **Bug repro.** For `kind: 'bug'`, the controller runs `reproCommand` before the first edit and expects it to fail. If it passes, edits stay blocked until the builder supplies a failing command or a `noReproReason`. After the turn the same command must pass. This matches "reproduce it end-to-end" with evidence the model cannot invent.
- **Risk stop.** The first write to a path where `assessRisk([path]).level === 'high'` stops and asks you once per request, showing the reason. This reuses `approve` and `assessRisk`. Headless runs are denied.
- **Project checks.** `detectChecks` reads `test`, `typecheck`, `lint` and `build` scripts from the baseline `package.json`, and `pytest` from `pyproject.toml`. The controller runs them through the sandbox before review. A failure goes back to the builder inside the same 3-round cap. No checks found prints `no checks ran`.
- **Evidence to the reviewer.** Add a `<checks>` block to the `reviewCandidate` prompt. If the builder changes `package.json` scripts, the output says so and the path is already high risk.

## Milestone 3: Stronger review

**Done means:** high-risk work gets several independent reviewers when you have them configured, and you hold the final word on any finding.

- **Reviewer panel.** `reviewers: ProviderConfig[]` runs `reviewCandidate` in parallel with `Promise.all`. It runs automatically at `risk.level === 'high'` or above 30 changed files, and on demand with `/review panel`. Any count from 2 to 5 works.
- **Dedupe without a model.** `mergeFindings` joins findings in the same file within 3 lines, keeps the highest severity and records `seenBy`. Two reviewers agreeing is shown, and it never lowers a must-fix.
- **Failure rule.** All reviewers unavailable means `BLOCKED`. Some unavailable means the run continues and the ready line names who was missing.
- **Second opinion.** A finding goes to a second reviewer with a verdict of `real`, `overthinking` or `unsure` when it is `major` with low confidence, or when the builder disputes it. `real` becomes must-fix. `unsure` comes to you.
- **Your overrule commands.** `/fix F3` promotes a note to must-fix. `/waive F2 reason` clears a must-fix for that exact fingerprint and is recorded in the receipt. Only you can type these. The model has no tool for them, and any later edit voids the waiver.

Files: `src/review.ts`, `src/workflow.ts`, `src/cli.ts`, `tests/v1-review.test.ts`, `tests/v1-workflow.test.ts`.

## Milestone 4: Ship

**Done means:** after `READY`, one typed command opens a PR, and Neura reports CI honestly.

- **`/pr` is a human command, never a model tool.** It requires `lastReview` to be ready and still current for the workspace fingerprint. It runs host Git with `AUTOMATIC_GIT_ARGUMENTS` and `automaticGitEnvironment`, stages only paths from the candidate snapshot, creates `neura/<slug>`, commits, pushes and runs `gh pr create`. With no remote it stops after the local commit. It never merges.
- **`/pr watch`** polls `gh pr checks` with a 30-minute limit and Ctrl+C. A red check prints the failing job and offers a fix turn, which goes through the same review loop.
- **`/review range BASE..HEAD`** reviews what actually landed, with a security and side-effects prompt. This is the screenshot's post-landing check, started by hand. Background loops need a long-running process and durable state, so they wait for #28.
- **Docs.** `AGENTS.md`, `CLAUDE.md` and `docs/STATUS.md` say `/ship` verifies only and that automatic Git shipping stays out. `/pr` keeps that rule because you type it each time. Update those files in the same change.

## Out of scope for this plan

Merge and deploy from Neura stay out. So do Plan mode, YOLO mode, background loops, automatic screenshots, persisted task state and context compaction. Each returns when real use shows the need. Nothing here changes the development-only status or the Mastra licence gate.
