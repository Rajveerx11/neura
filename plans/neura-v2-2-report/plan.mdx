# Neura v2.2 — Second Brain

## What I did

- **Audited the whole harness** — 12 extensions, live install, `mcp.json`, `auth.json`, `models-store.json`, pi 0.82.1 API surface. Zero drift between repo and live.
- **Found the real reason Neura feels weaker than Claude Code**: it only ever had one brain.
- **Shipped `/preset opus`** — Neura can switch to Claude Opus 5 per task instead of being locked to gpt-5.5.
- **Hardened preset switching** — dated catalog IDs now resolve by prefix, and a bad credential reports which model and which `/login` instead of throwing.
- **Tested, documented, committed, pushed** — `4444b7b`.

## Why this was the real problem

`auth.json` held exactly one credential. `models-store.json` cached exactly one provider. Neura was structurally incapable of running anything other than gpt-5.5 — while Claude Code was running Opus 5 on the same tasks.

That is not a harness gap. Every guardrail, checkpoint, proof gate, and memory file was working. The instinct to reach for Claude Code was correct, and it was about the model.

## Key takeaway

<Callout id="takeaway" tone="decision">

When a tool you built feels worse than the alternative, check what it is *made of* before adding features to it. Neura was not missing capability — it was missing a credential. Three days of not reaching for it was accurate signal about the model, and no amount of extra harness polish would have fixed it.

</Callout>
