Full interface redesign · approval artifact

Neura becomes a quiet engineering instrument.

One terminal-native visual language for startup, conversation, tool work, safety, approvals, proof, recovery, and handoff. Dense when useful. Calm by default. Every visible mark explains state or offers an action.

Chosen direction Quiet Instrument

Swiss information discipline, workshop warmth, and terminal speed without sci-fi theatre or generic AI-dashboard styling.

01

What changes

Direct response to supplied live screenshot.

Current screen works, but it does not feel authored. Every layer speaks at similar volume, so warnings, identity, continuity, input, and footer compete.

  • Skill collisions and package updates dominate first impression. They become one compact notice line with an on-demand detail view.
  • Full-width orange rules create a template-like frame. New shell uses neutral hairlines; accent marks only current focus or risk.
  • Continuity block leaves most of wide screen empty. New resume ledger uses stronger alignment and collapses after first prompt.
  • Human Away is green, which reads as “safe” or “complete.” Preview mode becomes amber, explicitly labelled, never communicated by color alone.
  • Footer mixes mode, model, branch, context, and MCP failure without priority. New footer has a fixed survival order at narrow widths.
  • Input is an empty box with no helpful state. New composer names mode, boundary, submit behavior, and the next useful action.
  • Assistant prose has no authored anatomy. New transcript defines labels, line length, list rhythm, code headers, receipts, errors, and copy actions.
  • Mode animations draw decorative rails. New motion confirms real boundary changes and completes in under 400 ms.
Design read: primary user is one expert operator; environment is desktop terminal; density is medium-high; mood is calm, exact, and slightly warm. The original six-line NEURA wordmark owns launch; one-cell signals and disciplined alignment own operational states.

Typography inside the terminal

Pi cannot choose the user’s terminal font. Neura therefore depends on roles, weight, alignment, and spacing—not font size tricks. Recommended Windows Terminal profile: Cascadia Mono or JetBrains Mono, 12–13 pt, normal weight, 1.2–1.3 line height. Installation must document this, never overwrite the operator’s profile.

Use one blank line between message groups, none inside compact receipts, and one-cell vertical plus two-cell horizontal panel padding.

GEOMETRY

Hairlines, not boxes

One border per focused surface. Left rails identify ownership. Rounded “web cards” do not belong in final terminal.

SYMBOLS

Small fixed vocabulary

◆ active, ◇ review, ✓ verified, × failed, · separation. Text always accompanies safety meaning.

Writing rules

  • Sentence case for messages. Uppercase only for short mode and phase labels.
  • Lead with outcome. Put evidence after it. Put next action last.
  • Never say “Something went wrong.” Name cause, impact, and recovery.
  • Use full verbs in tool receipts: read, edited, tested, blocked, queued.
  • Do not repeat branch, model, or mode in multiple simultaneous surfaces.
  • Never use green for a preview, pending, or merely allowed state.
  • Show duration only after one second or when it helps diagnose slowness.
  • Keep decorative copy, greetings, slogans, and personality out of operational states.

05

Copy and selection

Small affordance, fully specified.

Copy is keyboard-first because Neura is a TUI. Controls must remain discoverable without pretending terminal text has browser hover buttons.

ANSWER

Ctrl+X copy answer

Reuse Pi’s existing action. After success, action text becomes ✓ copied answer for 1.2 seconds without changing row width.

CODE

Ctrl+Shift+X choose block

Open a small overlay listing language, optional path, and first meaningful line. Enter copies. Escape returns focus unchanged.

HISTORY

/tree then copy

Reuse Pi’s selected-message copy path for older turns. Do not add permanent controls to every historical message.

Implementation choice: build the copy rail as an extension-owned below-editor widget and a custom overlay. Pi 0.83 already exports copyToClipboard and supports Ctrl+X; its core assistant renderer cannot be decorated by an extension. Do not patch global node_modules for v1.
  • Visible control label is C copy in a focused code header; accessible description is “Copy code block.”
  • Copy success uses check plus text. Color is supplementary.
  • Clipboard failure says why and offers terminal selection as fallback.
  • Copied text excludes visual labels, ANSI escapes, line numbers, and collapsed-state summaries.
  • Whole-answer copy preserves Markdown. Code-block copy returns raw fenced content without fences.
  • No share, export, or remote upload action appears beside copy.

08

Accessibility and input

Terminal limits do not remove accessibility duties.

  • All normal text pairs meet at least 4.5:1. Chosen text, muted, dim, and semantic colors pass against the canvas.
  • Focus and decision boundaries use high-contrast color plus text/glyph, never hue alone.
  • Every action is keyboard reachable. Escape always has a predictable cancel or interrupt meaning.
  • Mode change, copy success, errors, and approval results have explicit text for screen readers and logs.
  • NEURA_REDUCED_MOTION=1 remains supported; plan adds an operator setting and test coverage.
  • Animation is interruptible and never blocks input. Timers are disposed during reload and state replacement.
  • Selection and copied text never include ANSI escapes or purely decorative glyphs.
  • Links have visible text and OSC 8 enhancement; raw URL remains available when terminal capability is absent.
  • High-contrast Windows Terminal settings remain usable. Neura does not hardcode background assumptions into text-only output.
  • Color blindness test verifies Plan, YOLO, Human Away, success, warning, and failure remain distinct by wording and glyph.
Safety copy rule: “Human Away” is never shown without “Preview” until OS-enforced sandboxing and adversarial replay verification exist. That label survives every responsive breakpoint.

10

Definition of done

Observable, repeatable checks.

Redesign is done only when every state stays readable, truthful, fast, and stable in the real Windows terminal—not when one screenshot looks polished.

AUTOMATED

Deterministic harness

Load every extension; render all cockpit states at five widths; assert both legacy and compact ASCII marks; strip ANSI and assert visible width; fake timers for capability-latch motion; test latest-transition ownership; parse and copy answer/code blocks; verify theme token coverage.

INTERACTIVE

Real terminal smoke

Run /reload; confirm the NEURA wordmark appears once; resize live Windows Terminal; cycle modes rapidly; inspect capability changes; interrupt work; expand tools; copy an answer and code block; open the agent action request, health, undo, proof, and notice views.

ACCESSIBILITY

Contrast and motion

Check every foreground pair; inspect grayscale and red-green simulation; verify text/glyph redundancy; repeat full smoke with reduced motion and a Windows contrast theme.

ISOLATION

Plain Pi and live harness

pi remains stock while neura receives the shell. Installer drift must match repository source without patching global packages or overwriting settings.

Acceptance checklist

  • First screen shows the original NEURA ASCII identity, workspace, safety mode, last work, next action, and notice count within six seconds of scanning.
  • No wide orange rule, gradient, glow, emoji icon, decorative ASCII flourish beyond the launch wordmark, or unexplained animation remains.
  • Assistant output has predictable hierarchy for prose, lists, code, tools, diffs, links, errors, and evidence.
  • Copy answer, choose code block, and copy historical message all succeed and confirm without layout shift.
  • Human Away preview cannot be mistaken for success, sandboxing, or unlimited autonomy.
  • Approval reads as an agent action request: identity, task, intent, evidence, exact action, policy boundary, fallback, and grant scope are visible before choices.
  • Every failure tells operator what happened, what is affected, and what to do next.
  • Footer never wraps or hides mode/risk at 40, 56, 72, 92, or 120 columns.
  • Rapid Shift+Tab cycling updates enforced policy immediately, cancels stale transitions, and leaves only the newest capability verdict.
  • Reduced motion shows final policy state immediately with no pulse or spatial translation.
  • All current Modes v1 safety behavior and proof checks remain unchanged.

Research basis

First-party sources reviewed 2026-08-02.

The design borrows interaction principles, not another product’s visual skin. Local Pi 0.83 source remains the authority for feasibility.

Pi extension UI documentation

Grounds supported widgets, footer, working indicator, custom overlays, editor wrappers, message renderers, and clipboard integration.

Claude Code status line

Supports a short ambient status line, responsive data priority, event-driven refresh, and hiding status during focused permission UI.

Warp terminal Blocks

Supports grouping command and output into a meaningful unit with copy, navigation, re-input, and compact-mode behavior.

Warp Block Actions

Supports copy input, output, both, and conversation-level actions without making every line permanently noisy.

GitHub Copilot CLI modes

Confirms Shift+Tab mode cycling and the need to make permission differences explicit in a terminal interface.

Zed Agent Panel

Supports editable queued steering, checkpoints, follow mode, model/tool visibility, and recovery as first-class agent UX.

W3C text contrast

Sets 4.5:1 minimum for normal text. Proposed text, muted, dim, and semantic foregrounds meet this against the canvas.

W3C non-text contrast

Guides visible focus, boundaries, and control states; decorative separators may stay quiet, meaningful controls may not.

W3C animation from interactions

Supports disabling non-essential motion and respecting system/user reduced-motion preferences.

Windows Terminal appearance

Confirms font, size, line height, cursor, selection, foreground, and background belong to terminal profile configuration.

Dataset judgment: UI/UX Pro Max surfaced single-family terminal typography, strong keyboard feedback, short motion, explicit progress, and reduced-motion support. Its generic product-review layout, glassmorphism, glow, oversized typography, and back.out stagger were rejected because they conflict with a precise terminal cockpit.
