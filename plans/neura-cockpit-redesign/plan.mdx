# Neura Cockpit Redesign

## Outcome

Neura becomes one coherent engineering cockpit across the whole agent lifecycle. Launch, planning, execution, approval, verification, recovery, health, memory, agents, model control, degraded operation, closeout, and narrow-terminal behavior all use the same visual grammar.

Done means:

- Rajveer can identify current phase, active task, safety posture, and next action without reading old transcript output.
- Important states get a focused surface. Ambient metadata stays in the footer.
- Approval and proof are visible product states, not transient text.
- Every wide state has a deliberate narrow-terminal equivalent.
- Plain `pi` remains stock. Every Neura extension remains behind `NEURA`.
- Implementation follows the approved design system while plain `pi` remains stock.

<Callout id="approval-gate" tone="success">

Design approved on 28 July 2026. Forged Tungsten, Continuity Spine, the recommended density, session-only approval convenience, and on-demand agent detail are locked for implementation.

</Callout>

## Concrete product model

Top canvas shows complete target experience. Main lifecycle is:

1. **Brief** — establish outcome, constraints, proof, and allowed scope.
2. **Work** — show current step and meaningful operations without turning terminal into a dashboard wall.
3. **Proof** — expose verification state, evidence, and exact recovery action.
4. **Handoff** — close with changed scope, proof, remaining decisions, and next manual action.

Launch restores continuity through LAST, NOW, and NEXT. Approval, recovery, health, memory, agents, and model control are contextual surfaces opened only when needed.

<Callout id="shell-decision" tone="decision">

Use one stable terminal shell. Keep transcript and composer central. Add a narrow phase ribbon above transcript, a responsive ambient footer below composer, and temporary panels or popovers for decisions. No permanent sidebar or inspector.

</Callout>

## Research synthesis

The design applies patterns from current official product references:

- Linear reduced chrome noise while increasing hierarchy and density, then stress-tested the direction across every major view and state. Neura should use one chrome system and validate it across the full state matrix, not only launch. [Linear redesign](https://linear.app/now/how-we-redesigned-the-linear-ui)
- Warp makes control transfer explicit: proposed action, allow once, session-level policy, refine, or take over. Neura approval should name risk and scope, with session-only convenience. [Warp Full Terminal Use](https://docs.warp.dev/agent-platform/capabilities/full-terminal-use)
- Claude Code treats status line as local, responsive ambient data and hides it during permission prompts. Neura footer should carry model, branch, context, cost, and current operation; approval owns focus when open. [Claude Code status line](https://code.claude.com/docs/en/statusline)
- Claude Code permission evaluation is deny-first: blocking rules outrank allow rules. Neura visual hierarchy must never make convenience look stronger than safety. [Claude Code permissions](https://code.claude.com/docs/en/permissions)
- GitHub separates running state from completed conclusion and links failed checks to detailed evidence. Neura proof should distinguish queued, running, passed, failed, skipped, and unavailable. [GitHub status checks](https://docs.github.com/en/pull-requests/reference/status-checks)
- Vercel puts failure summary beside status, then reveals logs for root-cause inspection. Neura degraded and proof-failure states should show one decisive error plus a direct next action, with verbose output behind detail. [Vercel build troubleshooting](https://vercel.com/docs/deployments/troubleshoot-a-build)

## Design system

Forged Tungsten is the identity. Neutral chrome carries the interface. Burnt copper is the only brand accent. Semantic success, warning, and error colors appear only for real outcomes or risk.

Visual rules:

- **Hierarchy:** phase label, active objective, current evidence, secondary metadata.
- **Density:** one major surface per state; maximum two footer lines; panels stay within the platform ten-line widget limit.
- **Shape:** flat bordered surfaces, one-cell rules, compact pills, no decorative shadows, gradients, or glow.
- **Typography:** terminal monospace; uppercase reserved for phase or verdict; sentence case for actions.
- **Motion:** text-state transitions only. No spinners that obscure state; running work uses a stable active marker plus elapsed operation label.
- **Language:** terse, factual, no emoji, no Devanagari.
- **Color:** copper means active identity and focus; semantic colors appear only for outcomes or risk.
- **Debloat:** one brand accent, three elevations, zero ambient decoration, detail on demand.

## Interaction rules

### Phase ribbon

One line above transcript. It owns phase, objective, and progress:

`NEURA / WORK   Cockpit redesign   3/5`

On narrow terminals:

`WORK  3/5  cockpit redesign`

Ribbon disappears at idle launch, where the Continuity Spine owns hierarchy.

### Footer

Footer carries only ambient session facts:

`gpt-5.5 · main · context 34% · $0.42`

Optional second line carries live operations:

`checkpoint · reviewer: active · proof: queued`

Collapse order: cost, context bar detail, branch, operation detail. Model and current phase survive longest.

### Focused surfaces

- Approval suppresses footer detail while open.
- Proof panel replaces noisy raw verification output with one status row per check; raw details remain inspectable.
- Recovery previews exact snapshot and restores current-state reversibility.
- Health, memory, agents, and model control open on command; none become permanent chrome.
- Closeout uses existing end-of-iteration report content, presented as a compact handoff record.

## Scope

Included:

- Terminal UI and state coordination.
- Existing commands and harness behaviors.
- Responsive rendering and deterministic verification.
- Copy cleanup needed for coherent states.

Deferred:

- GUI application, web dashboard, telemetry, cloud persistence, new MCP servers.
- Changes to proof-of-work engine.
- Redesign of stock `pi`.
- New logo, emoji, Devanagari, or permanent sidebars.
- LinkedIn post and infographic revision.

## Risks

- **Widget cap:** every widget remains at or below ten lines. Long evidence moves into notifications or command-driven detail.
- **Stale context:** async publishers must tolerate session replacement and fail soft.
- **State contention:** multiple extensions may publish simultaneously. Priority is approval, failure, proof, active work, ambient.
- **Noise:** operation updates must be debounced and semantic; raw tool calls never become a permanent feed.
- **Safety regression:** approval convenience stays session-only. Deny rules and unavailable-interaction blocks remain stronger.
- **Plain pi leakage:** every touched extension keeps the `NEURA` gate; theme remains session-only.
