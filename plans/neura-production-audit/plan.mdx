# Neura audit: production gaps and terminal polish

Neura on `main` (`d44900e`) is a working development build. Work, Learn and YOLO run, the 23 test suites exist, and the last three CI runs on that commit passed. It is not shippable yet. One legal gate, three engineering gates and about ten missing agent features stand between this build and a release other people can install.

I read all 18 files in `src/` and the status, readiness and parity documents. I also went through the 33 open issues and the README screenshots. I changed no code.

### Engineering debt before a release

- `main()` in `src/cli.ts` is one 470-line function holding every command, the turn loop and all state. It is the hardest file to change safely.
- `agent/extensions/` (19 files) and `legacy/pi/` are never loaded. They ship as dead weight and confuse the source map.
- `memory` and tool inputs are typed `any` in `cli.ts`, `runtime.ts`, `session.ts` and `acp.ts` (#26).
- The live WSL sandbox test does not run in PR CI. A sandbox regression can merge green.
- `docs/STATUS.md` is 397 lines and about 250 of them describe the retired Pi build. Version `2.6.0-rc.1` is a Pi-era number.

Smaller items: `/new` and `/clear` do the same thing and could be one command. Code blocks have no syntax colour. `/help` ends with a development notice on every call. A long task finishes with no bell or title change. Command history does not survive a restart.

<Callout id="keep" tone="info">

**Keep these.** The copper accent, the single erasable activity row, the `NO_COLOR` and `TERM=dumb` fallbacks, and the `YOLO · DANGER` label in plain words. All four are covered by tests and they are what makes the terminal feel calm.

</Callout>

## Key takeaway

A release is blocked by its slowest gate, and here that gate is a licence question you can answer without writing code. Check the non-code blockers first. They cost nothing to start and they decide whether the code work can ship at all.
